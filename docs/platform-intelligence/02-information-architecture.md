# 功能模块与信息架构

## 导航顺序

第一层是平台。现在是 Afun-MX 和 Betroia。以后可以加平台，也可以按国家过滤。不把两个平台的人数或金额加在一起当默认首页。两个平台的汇率不同，人数也不能相加后当成一个用户池。

第二层是这个平台里的页面：

1. 总览
2. 波动
3. 用户
4. 支付
5. 游戏
6. 数据中心
7. 指标口径
8. 分析记录

AI 助手和团队权限不进第一版导航。架构上留入口，等阶段 6 和阶段 7。

## 模块和现在的数据能不能做

| 模块 | 第一版 | 原因 |
| --- | --- | --- |
| 经营总览 | 做 | 日报里有活跃、注册、充值、提现、投注、输赢 |
| 波动分析 | 做时间和已核对分项 | 没有渠道、游戏、支付明细，就不能做这些维度的贡献 |
| 指标归因 | 只做已经对账的等式 | 见指标文档 |
| 用户分析 | 做日报上的用户分项 | 没有单用户明细，不能做真正的留存cohort |
| 支付分析 | 只做充值、提现、充提差 | 没有通道和成功率 |
| 游戏分析 | 只做全平台投注、返奖、公司输赢 | 没有厂商和游戏行 |
| 数据中心 | 做 | 导入、模板、校验、版本都从这里进 |
| 指标管理 | 做口径说明 | 第一版口径少，但必须写死，不能散落在页面里 |
| AI 助手 | 不做 | 阶段 6，而且只能读已计算结果 |
| 分析记录 | 先做本地笔记 | 不共享。可以记下结论、证据日期和待补的报表 |

## 从总览到明细

总览上的每个数字都能点。点进去是这个指标的分析页，固定四块：

1. 当期值、对比期值、差额、百分比。
2. 选定日期范围内的趋势。
3. 已核对的分项贡献。没有分项就写缺哪张报表。
4. 原始日报中参与计算的列，方便对账。

分析页不跳到另一套口径。它用的就是指标管理里登记的那一条。

## 以后加人或加平台时怎么接

每条标准化数据都有：平台、市场、币种、业务日期、来源文件、导入批次。

以后的权限只是决定谁能看哪个平台。第一版不检查登录，但字段先留着，避免以后把 Afun 的数拷进 Betroia。

报告共享是「把一次分析记录发给别人」。第一版只把记录存在本地。阶段 7 再加所有者和只读链接。
