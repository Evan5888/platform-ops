# 指标体系与归因引擎

## 指标怎么登记

每个指标有一张登记卡，计算和页面都读这张卡，不在图表里另写公式。

登记卡包含：

- 名称，用报表原词，直到你确认别名。
- 意思。
- 粒度。现在都是平台日。
- 类型：人数、金额、比率、差额。
- 公式。
- 源列。
- 是否允许跨币种换算。人数不允许。
- 对账状态：已对账、只展示原值、不能用。
- 适用平台。现在两家都适用，但仍按平台存结果。

## 第一版可计算的指标

这些列在日报里直接存在，结束日的值就是该列的值。

| 指标 | 类型 | 换算 | 对账状态 |
| --- | --- | --- | --- |
| 活跃人数 | 人数 | 否 | 原列。是否等于 DAU，等待你确认 |
| 注册人数 | 人数 | 否 | 原列 |
| 充值人数 | 人数 | 否 | 原列，且等于首充人数加老用户充值人数 |
| 首充人数 | 人数 | 否 | 原列 |
| 新充人数 | 人数 | 否 | 原列。不是充值人数的补集 |
| 老用户充值人数 | 人数 | 否 | 原列。没有对应金额列 |
| 充值笔数 | 人数类计数 | 否 | 原列 |
| 充值金额 | 金额 | 仅在缺少该币种原值时 | 原列 |
| 首充金额 | 金额 | 同上 | 原列 |
| 新充金额 | 金额 | 同上 | 原列 |
| 提现金额 | 金额 | 同上 | 原列 |
| KOL工资 | 金额 | 同上 | 原列。业务含义待确认 |
| 充提差 | 金额 | 同上 | 原列，且等于充值金额减提现金额再加 KOL工资 |
| 投注金额 | 金额 | 同上 | 原列 |
| 返奖金额 | 金额 | 同上 | 原列 |
| 公司输赢 | 金额 | 同上 | 原列，且在本批数据中等于投注金额减返奖金额。是否叫 GGR，等待确认 |

全量 Arppu 和首充 Arppu 是原列，同时等于对应金额除以对应人数，允许报表的舍入误差。第一版展示原列，旁边可以标出重算值。两者不一致时以原列为准，并记一条校验。

## 明确不登记的指标

- DAU、GGR、充值成功率、用户留存率、新访问 IP、推广消耗、厂商占比。源数据或口径还没确认。
- 老用户充值金额。列不存在，禁止用充值金额减新充金额代替。
- 由充值人数减新充人数得到的「老用户人数」。46 天都不等于老用户充值人数。

文件里的复登率、复充率、付费率先只留在原始表。不放进归因，因为还没有核对分母。

## 对比怎么算

默认对比是结束日的前一个墨西哥自然日。

绝对变化 = 当期 − 对比期。百分比 = 绝对变化 / 对比期。对比期缺失，或者对比期为 0 而当期不是 0，百分比留空。不把缺失写成 0 后再算一个百分比。

趋势使用所选开始日到结束日之间、文件里实际存在的日期。

「过去七天」是结束日含当天、向前找已有日报，最多七个日期的合计。这是每日数字相加。对人数来说，这不是七天独立用户数。页面问号必须写清这一点。

## 归因引擎

引擎只做三步。

1. 取出当期和对比期的已对账指标。
2. 如果父指标有已对账的加法拆分，计算每个子项的差额，以及子项差额占父项差额的比例。
3. 把结果放进四层，不允许混写。

当前可以做的加法拆分只有一条：

充值人数的变化 = 首充人数的变化 + 老用户充值人数的变化。

这是人数恒等式的差分，不是业务原因。页面标题用「分项变化」，不用「原因是老用户」。

金额可以做的量化关系，是把已对账的乘除改写成贡献。例如充值金额的变化，可以分解成充值人数变化和人均充值变化。人均充值使用充值金额除以充值人数，并与全量 Arppu 对账。分解结果叫「数量与人均的贡献」，不叫「因为支付失败」或「因为活动」。

公司输赢的变化，在等式仍然通过校验时，等于投注金额变化减去返奖金额变化。彩金不为 0 的新日期如果让等式失败，这一层自动停用，只保留原始列。

充提差的变化沿用已对账算式：充值金额变化、提现金额变化、KOL工资变化。不解释 KOL工资代表补贴还是成本，直到你确认。

## 四层输出

- **已核对的变化**：当期、对比期、差额、百分比，以及参与的批次号。
- **可量化的驱动**：上面那些等式算出来的分项。每一行能回到源列。
- **可能的业务假设**：第一版不自动写。只有你在分析记录里填写的句子会出现在这里，并标成「未经数据证实」。
- **尚待验证**：列出缺的报表。例如充值金额下降后，若要知道是不是某个支付通道，系统写「需要支付通道日报」，不排名一个不存在的通道。

## 对账

每个指标的测试用固定日期比对原始 CSV，而不是比对上一次程序输出。至少覆盖 2026-11-15 的两个平台、比索文件，以及一条等式在 46 天上的通过次数。

覆盖导入之后，旧批次的对账结果保留。正式页面用新批次，分析笔记仍指向它保存时的批次。
