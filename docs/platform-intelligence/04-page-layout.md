# 页面结构与布局

## 整体

桌面优先。左侧是这个平台内部的页面导航，顶部是平台切换、日期和币种。主区域先放数字，再放图，再放表。

浅色是默认。深色作为同一套组件的另一种配色，不单独做一套页面。第一版可以先只做浅色，深色在阶段 1 的布局里留出主题开关，不要求所有图都先完成深色。

视觉要像企业分析工具：留白清楚、数字对齐、层级稳定。不照搬某一家后台的登录区、CRM 或监控配置。那些块现有报表里没有。

参考你给过的后台首页，只借鉴三件事：上面先选平台，中间是少数几张大指标卡，下面分用户和游戏两块。不借鉴里面的访问 IP、厂商假占比、登录 IP 和播报。

## 顶部

- 平台：Afun-MX、Betroia。选中态清楚。没有「全部平台」作为默认。
- 日期：开始、结束。结束日是卡片上的「当天」。
- 币种：MXN、USD。
- 当前平台汇率：1 美金等于多少比索，两位小数。问号里说明这是金额列的中位数，人数不换算。
- 导入入口。

## 左侧

总览、波动、用户、支付、游戏、数据中心、指标口径、分析记录。

当前做不到的页面仍然可以点开，里面是空状态和缺的报表名称，不是禁用得没有入口。这样你能看见路线，也不会误以为已经有分析。

## 总览

标题是「数据看板」。

第一行三张卡，用文件原名，不用未确认的别名：

- 活跃人数
- 注册人数
- 首充人数

每张卡有结束日的数，以及「较前一日」的百分比。前一日没有则显示横线。活跃人数卡可以带所选日期范围的细趋势，点是真实日期，不补 0。

第二行两块：

- 用户：新充人数、充值人数、充值金额。每项有结束日，以及结束日往前数到的已有日期合计。问号说明这是每日相加，不是去重人数。
- 游戏：投注金额、返奖金额、公司输赢。没有厂商行时，不画占比条。

卡片可以点，进入该指标的分析页。

## 指标分析页

上面是当期、对比期、差额、百分比和趋势。

中间是驱动表。只列出已核对的分项。例如充值人数的分项是首充人数和老用户充值人数。每一行有对比期、当期、差额、占父指标差额的比例。比例分母为 0 时不计算。

下面是对账表：这一天原始列的值，和算出来的值并排。不一致就标红，不自动改原始值。

最下面用四个固定标题分开写：已核对的变化、可量化的驱动、可能的业务假设、尚待验证。第一版「可能的业务假设」默认是空的，只能由你在分析记录里手写。系统不自动生成原因。

## 用户、支付、游戏

这三个页面是总览的展开，不是另一套数字。

用户页列新充、首充、老用户充值人数，并重复那条不能成立的关系：不能用充值人数减新充人数得到老用户。

支付页列充值金额、提现金额、KOL工资、充提差，并展示已核对的算式。

游戏页列投注、返奖、公司输赢。厂商表在没有游戏报表时只有表头和空状态。

## 数据中心

左列是导入批次，右列是这次文件的预览、识别出的报表类型、将要使用的字段映射、校验结果。确认前不写入正式指标。

## 指标口径

一张表。每行是指标名、业务意思、公式、来源列、适用平台、是否已对账、不能使用的别名。

## 分析记录

列表加编辑。字段：平台、日期、指标、你的结论、待跟进、系统附上的证据快照。证据快照是当时的数字拷贝，以后源数据被覆盖时，笔记仍指向当时的批次。

## 空状态和问号

长说明不铺在页面上。必要的口径放在问号里，鼠标悬停或键盘聚焦时出现。空状态只写缺什么，例如「没有游戏明细报表」。
