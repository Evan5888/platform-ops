## 原型里已经能点的东西

- 切换平台、日期、比索/美金、浅色/深色。人数不随汇率变。
- 总览三张大卡、一条活跃人数折线、用户块和游戏块。点指标进入分析页。
- 波动页是全部指标相对前一日的表。
- 分析页有当期、对比期、差额、百分比、趋势、分项表、对账，以及四层文字：已核对的变化、可量化的驱动、可能的业务假设、尚待验证。
- 数据中心有三批假文件。确认只改这一页上的字，不读文件。
- 指标口径页是一张说明表。分析记录只存在当前打开的页面里，刷新就没了。
- 用户、支付、游戏页只重排了总盘数字。没有渠道、通道、厂商行。

原型上的每一个数都是编的：日期 2026-03-01 到 2026-03-14，演示汇率 Afun-MX 为 20、Betroia 为 10。真实日报是 2026-10-01 到 2026-11-15，汇率中位数是另一套数，只存在运营看板里。两套数字没有画在同一张图上。

原型的数据中心预览表也是写死的三行，和总览曲线不是同一次导入。

## 必须保留的口径

这些已经对过或你已经确认，重设计不改公式：

- 平台分开看。没有「全部平台」合计。
- 活跃人数可以叫 DAU。公司输赢可以叫 GGR。页面同时保留原列名。
- 充值人数 = 首充人数 + 老用户充值人数。
- 充值人数 − 新充人数，不是老用户。
- 没有老用户充值金额，禁止用总充值去减。
- 公司输赢（GGR）在本批彩金为 0 时 = 投注金额 − 返奖金额。彩金不为 0 时要再核对。
- 充提差 = 充值金额 − 提现金额 + KOL工资。KOL工资是付给网红达人、经平台账户发给他们提现的钱。
- 人数不换算。金额优先用该币种原文件。
- 「总计」行不参与计算。缺的日期不当成 0。
- 过去七天的人数是每日人数相加，不是去重人数。
- 相关不是原因。系统不自动写业务结论。
- 导入窗口：墨西哥自然日结束后再过 3 小时。
- 下一阶段服务用 FastAPI，分析库用 DuckDB。这一步还不写。

## 对照你指出的问题

1. 页面仍围着用户和游戏转。原型总览的下半部分就是用户块和游戏块。线上看板的主导航也是这两块。
2. 没有完整的分析架构。模块名字在，但没有「发现异常 → 打开诊断 → 看贡献 → 留下调查」这条路径。
3. 总览 KPI 是三张大竖卡，数字用了很大的字，下面留白多。
4. 趋势只有一条活跃人数折线。没有对比期叠线，没有柱状、瀑布，也没有可选的同比环比。
5. 波动是全表，归因是另一页上的四段文字。不是一个可操作的诊断工作台。
6. 结束日的数和「过去七天合计」叠在同一张卡上，口径没有先讲清楚。
7. 视觉是浅色圆角卡片页，密度和层级不像分析工具。
8. 日期范围只作用于那一条趋势。卡片始终是结束日，七天合计又是另一套加法。筛选器里没有「对比周期」。
