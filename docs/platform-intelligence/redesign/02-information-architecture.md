# 信息架构

产品名：Platform Intelligence，界面标题用「经营分析」。

它要回答的仍然是五件事：现在怎么样，什么变了，变化能拆成哪些已核对的部分，还缺哪张报表，下一步查什么。展示数字是手段。主路径是发现异常并进入诊断。

## 导航

左侧固定，分成三组。组名是中文，模块英文名留在组内第二行，字号更小。

**分析**

- 经营总览 Overview
- 波动归因 Diagnostics

**专题**

- 用户分析 Users
- 充值与提现 Payments
- 游戏与厂商 Games

**治理**

- 数据中心 Data
- 指标中心 Metrics
- 分析报告 Reports

AI 助手和多人权限不进这一版导航。信息架构里留位置，等后面的阶段。不在侧栏放一个点进去是空的「即将推出」。

当前平台名写在侧栏顶部，不写成可以切换的第二套菜单。平台切换在顶栏。

## 顶栏

所有分析页共用，改一处，下面的页跟着变。

- 平台：Afun-MX 或 Betroia。一次只看一个。没有「全部平台」。
- 分析区间：开始日、结束日。只影响趋势，以及你明确选了「区间合计」时的 KPI。
- 统计口径：`结束日` 或 `区间合计`。见下面的口径规则。
- 对比周期：`前一日`、`上周同日`、`上一等长区间`。
- 币种：比索或美金。旁边是该平台汇率，问号说明人数不换算。演示数据时，汇率旁必须有「演示」。
- 主题：浅色 / 深色。
- 数据中心入口。

顶栏不放业务结论，不放大数字。

## 口径规则

这是这次要先定清楚的统计规则。

**结束日。** KPI 取分析区间最后一天的原列。趋势图仍画出区间里每一个已有日期。这是默认。适合看「这一天经营怎么样」。

**区间合计。** KPI 改为区间内已有日期的相加，并标明「日合计 · N 天」。人数不是去重。缺的日期不加 0。如果两边的天数不同，百分比旁边写明两边各有几天。

**对比。**

- 前一日：结束日的前一个已有业务日。中间缺天不补 0，百分比留空并写「没有前一日」。
- 上周同日：结束日往前 7 个日历日。那一天没有报表，百分比留空。
- 上一等长区间：与当前分析区间等长、紧挨在前面的日历区间。只加已有日期。

不提供「去年同期」。现有日报没有满一年，做出来会是空的。有满一年数据后再加。

涨跌颜色只表示方向，不表示好坏。提现变多不会被画成好消息。

## 八个模块各自负责什么

**经营总览。** 一眼看到结束日（或区间合计）、哪些指标波动大、点进去做诊断。不在这里展开渠道或厂商。

**波动归因。** 诊断工作台。选一个指标，看变化、趋势、已核对因素、维度贡献和下钻。没有明细的维度保持空状态。

**用户分析。** 增长、活跃、首充、充值，以及已经对上的用户分项（首充、老用户充值人数）。留存和用户分层在没有对应报表时是空状态。不把充值人数减新充人数写成老用户。

**充值与提现。** 充值金额、充值人数、充值笔数、提现、KOL工资、充提差，以及它们的趋势。支付成功率和支付通道在没有通道日报时是空状态。

**游戏与厂商。** 保留投注金额、返奖金额、公司输赢（GGR），加上趋势和进入归因的入口。厂商贡献表有表头，没有游戏明细时不填数。

**数据中心。** 导入、映射、校验、历史批次、来源。这一版设计把它的位置定下来。功能仍等到你确认方案之后的导入阶段。

**指标中心。** 指标定义、公式、口径、指标之间的计算关系。总览和归因都读这里，不在图表里另写公式。

**分析报告。** 你保存的结论、异常记录、调查备注。系统附上当时的数字和批次，不自动生成原因。

## 主路径

1. 打开经营总览，顶栏已经是一个平台和一段日期。
2. 看紧凑 KPI 和异常条。异常只表示变化幅度或对账失败，不解释原因。
3. 点一个指标，进入波动归因，并且带着当前的平台、区间、口径、对比和这个指标。
4. 在工作台里看趋势、瀑布和维度。能算的因素来自已核对等式。不能算的维度写明缺哪张报表。
5. 需要记下判断时，把当前证据存进分析报告。句子由你写。

专题页是同一套指标的业务分组，不是另一套数。专题页上的每个数也能进波动归因。

## 以后加人和加平台

每条数据仍带平台、市场、币种、业务日期、来源和批次。权限以后只决定能看哪个平台。第一版不登录。报告以后可以共享，这一版只设计成「可保存的一条分析」，不设计账号。
